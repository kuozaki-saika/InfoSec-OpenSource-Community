# 整改说明与验证记录

## 审查发现的问题

| # | 问题 | 严重程度 | 状态 |
|---|------|----------|------|
| 1 | 原 `denoise_document.py` 无输入校验，任何人可直接传入任意路径 | 高 | 已修复 |
| 2 | 原代码使用 `os.path.join` 直接拼接 testPath，无路径穿越防护 | 中 | 已修复 |
| 3 | 原代码无任何错误处理，crash 时暴露完整堆栈 | 低 | 已修复 |
| 4 | pickle.load 加载用户上传模型的风险 — 当前仅加载本地受信文件，风险可控 | 低 | 已记录 |

## 整改措施

### 问题1 & 2：输入校验
- **改了什么**：API 层新增文件扩展名白名单 + `secure_filename` + UUID 重命名
- **怎么改**：完全拒绝非白名单格式，文件名不再直接用于任何路径拼接
- **验证条件**：上传 `test.php`、`test.exe` → 400 拒绝，上传 `../etc/passwd` → 转义为安全文件名

### 问题3：错误处理
- **改了什么**：`try/except` 包裹核心逻辑，统一返回 JSON 错误
- **怎么改**：错误类型分 400/413/422/429/500，错误信息不包含内部路径
- **验证条件**：传入损坏的图片 → 422，传入超大文件 → 413

### 问题4：pickle 安全
- **改了什么**：保持 `pickle.load` 仅用于本地训练好的模型文件
- **验证条件**：确认 API 不接受用户上传 pickle 文件

## 验证方式

1. 启动 API 服务：`python api_server.py`
2. 合法请求：`curl -F "file=@test.png" http://127.0.0.1:5000/denoise` → 200
3. 非法类型：`curl -F "file=@test.php" http://127.0.0.1:5000/denoise` → 400
4. 超大文件：`curl -F "file=@large.bin" http://127.0.0.1:5000/denoise` → 413
5. 高频请求：连续发送 25 次请求 → 第 21+ 次返回 429
   — 所有项均通过
