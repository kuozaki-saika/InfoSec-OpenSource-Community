# 整改前后对比

## 架构对比

### 改造前
```
用户 → CLI 命令行 → denoise_document.py（直接读取本地 test/ 目录）
```
- 无输入校验
- 无网络暴露
- 无错误处理

### 改造后
```
用户 → HTTP POST → Flask API → 文件校验层 → 去噪引擎 → JSON 响应
                              ├── 扩展名白名单
                              ├── 大小限制 16MB
                              ├── secure_filename
                              ├── UUID 重命名
                              ├── MIME 二次校验
                              └── 频率限制
```

## 代码量对比

| 指标 | 改造前 | 改造后 |
|------|--------|--------|
| 安全校验行数 | 0 | ~40 |
| 错误处理分支 | 0 | 6 |
| 访问控制 | 无 | IP 频率限制 |
| 临时文件清理 | 无 | 处理后立即删除 |

## 安全能力新增

| 安全控制点 | 改造前 | 改造后 |
|-----------|--------|--------|
| 文件类型校验 | 无 | 扩展名白名单 + MIME |
| 路径穿越防护 | 无 | secure_filename |
| 大小限制 | 无 | 16MB |
| 频率限制 | 无 | 20次/分钟/IP |
| 错误信息脱敏 | 无 | 统一 JSON 格式 |
| 临时文件清理 | 无 | finally 块确保删除 |
